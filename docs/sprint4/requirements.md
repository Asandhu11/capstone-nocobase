## Deliverable 1 - individual end-to-end testing

- Work in a `sprint4-yourname` branch created from team `main`.
- Identify 5-6 real user tasks and write a usability testing plan.
- Add a Selenium service to Compose and runnable tests that perform those tasks
  in a real browser. Python is the instructor's suggested language.
- Submit a ZIP containing Compose, the updated README with test instructions,
  and the bind-mounted data for every service. Include the tests and required
  startup files so the package actually runs.

Outstanding requires representative, non-trivial tasks and runnable Selenium
tests. Trivial tasks with runnable tests are Satisfactory. Late, incomplete or
unrunnable work is Unsatisfactory. The six-task plan includes sign-in plus
counting, persistence, limits, filtering and historical reporting.

## Deliverable 2 - individual user tests

- Test with at least three people outside this class.
- Have each participant attempt the tasks in the plan.
- Document every issue in an Observations section and upload the plan.

Outstanding requires both conducting the tests and analyzing their results to
identify improvements. Tests without clear analysis are Satisfactory. Late or
incomplete work is Unsatisfactory. Missing timings or ratings should be marked
not recorded rather than reconstructed.

The participant website is http://localhost:13004. Prepared P1-P3 prompts and
empty note sheets are in `~/Documents/Capstone_Sprint4/Sessions/`. These are
facilitator materials, not evidence that a session has happened.

## Deliverable 3 - team discussion

After everyone completes Deliverables 1 and 2, hold a Microsoft Teams meeting,
turn on transcription and discuss findings. Select 8-10 pressing problems or
requested features, then create one GitHub issue for each selected item.
Ayoola is handling the transcript and live sessions.

Outstanding requires transcript evidence of leadership; Satisfactory requires
evidence of participation. Minimal or absent evidence is Unsatisfactory.
Use the discussion agenda to facilitate comparison, prioritization and clear
spoken decisions. A prepared agenda is not a meeting record.

Instructor-linked issue guidance:
https://github.com/codeforamerica/howto/blob/master/Good-GitHub-Issues.md

The guide and its linked issue template were reviewed October 25. Use a clear
description, reproduction steps for bugs, relevant files, available screenshots
and an actionable checklist. Keep each issue focused. Add evidence, expected
behavior and acceptance criteria where they clarify the report. Never copy the
template's example screenshot or claim an uncaptured participant quote.

## Overall grading

The written instructions say two Outstanding deliverables earn Outstanding,
two Unsatisfactory deliverables earn Not Satisfactory, otherwise Satisfactory.
The attached rubric also displays overall thresholds of 0, 210 and 270 points.
Retain both as displayed; do not substitute invented grading rules.
