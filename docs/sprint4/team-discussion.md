## Draft GitHub issue structure

**Title:** concise symptom and trigger, or the user outcome for a feature.

**Type and impact:** bug / usability / feature; who is affected and why it matters.

**Environment:** branch/commit, browser, viewport and tested role.

**Evidence:** observation IDs and number affected / number who attempted;
Selenium test name and evidence path if relevant. Use anonymized participant IDs.

**Steps to reproduce:** starting state, account role and exact actions with
fictional data. For a feature, give the user scenario instead.

**Expected behavior:** what the user should be able to do.

**Actual behavior:** what was observed; quote exact visible errors where useful.

**Acceptance criteria:** observable checks proving the issue is resolved.

**Priority rationale:** severity, frequency and workaround; include the team's
reason for selecting it. Avoid claiming a technical cause without evidence.
